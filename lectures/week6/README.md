## Before you teach it

* **Run the notebook once on a T4 and write the numbers on the slides.** The tables marked `______` and the "expected" ranges (matmul ~30 ms at n=4096, ~4–5 TFLOP/s) are estimates from the T4 specs, not measurements. The notebook logic was tested end-to-end on a CPU with a NumPy stand-in for CuPy, so correctness is checked but GPU speed is not.
* Colab's free CPU has ~2 vCPUs, so speedups against it look larger than against a workstation. Say so in class.
* The T4 is PCIe 3.0 x16 (~12 GB/s in practice), not PCIe 4.0.

## Expected take-aways

1. A training step is a few matmuls plus cheap element-wise work; the GPU wins when compute per kernel ≫ launch and transfer overhead.
2. Time GPU code only after `synchronize()`; keep data on the device; stay in `float32`.
3. Matmul is compute-bound (FLOP/byte grows like n/6), element-wise ops are bandwidth-bound.
4. The four course questions on the GPU: split = one thread per element, assign = hardware block scheduler, move = `asarray`/`asnumpy` over PCIe, wait = asynchronous launches + `synchronize`.
